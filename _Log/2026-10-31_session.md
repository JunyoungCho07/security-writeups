# Session 2026-10-31 — CFG 에서 UAF 로, 그리고 ORW 까지

> 4문제 해결. 첫 번째는 리버싱(IDA), 나머지 셋은 pwn. 마감이 5일치를 한 번에 묶었다.

## 0. 세션 성격

§1.4 유지 — 풀이·payload·다음 명령은 주지 않았다. exploit 파일은 전부 JY 가 직접 썼고 에이전트는
개념·환경 사실·코드 리뷰만 했다 (2026-09-28 규칙 유지).

## 2. ⭐ 이번 묶음의 수확

1. **반환값 연쇄.** "stack 에는 공격 전에 아는 값만 쓸 수 있다" → 실행 중에야 정해지는 값
   (fd, 읽은 바이트 수)은 `rax` 에서 `mov` gadget 으로 옮긴다. `mov` 는 다음 `pop rax` **앞**. (`ROP` §H)
2. **UAF 는 다른 종류의 버그.** 공간(BOF)이 아니라 시간(수명). canary·오프셋 공식이 개입하지 않고
   "무엇이 그 칸을 다시 받는가"를 본다. (`Use_After_Free`)
3. **JY 가 스스로 던진 좋은 질문들.** "꼭 `rax` 가 필요한가, 내가 덮어쓰면 안 되나?"(→ 가능하지만 환경
   의존: 래퍼가 fd 를 더 열면 깨진다), "셸을 따면 안 되나?"(→ 가능, 단 문자열 주소가 문제 → 고정
   쓰기 영역에 두는 아이디어를 **스스로 제시**).
4. **v1→v3.** ORW 를 처음 풀고 나서 에이전트가 짚은 두 가지(읽기 길이가 버퍼 크기 초과, `write` 인자가
   살아남은 레지스터에 의존)를 두 번에 걸쳐 직접 고쳤다.

## 3. 🔴 에이전트 오류 — 정직하게

### 3.1 IDA 문제에서 방향을 잘못 줬다
- "graph 한도를 올리는 건 권장되지 않는다"고 했는데 **이 문제에서는 한도를 올리는 것이 정답 경로**였다.
- "chunk 는 노이즈니 건너뛰라"도 틀렸다 — 그래프 전체가 데이터였다.
- `main` 이 실행되는지 의심하는 방향도 틀렸다 (`_start` 가 호출한다).
- `?` segment 를 bss 로 설명했다가 정정했다 (둘 다 0 인 빈 segment).
- 교훈: **"일반적으로 권장되지 않는다"는 말은 문제의 의도를 모를 때 쓰면 안 된다.** 도구 한도를 올릴지는 *왜 큰가*를 먼저 묻고 정한다.

### 3.2 macOS 에서 안 되는 플래그를 안내했다
- `objdump --disassemble=<함수>` 는 **GNU 전용**이다. 이 Mac 의 LLVM `objdump` 는 `--disassemble-symbols=` 이다.
  JY 가 실행하기 전에 내가 먼저 확인했어야 했다. 이미 `Tools/objdump` 에 "LLVM/GNU 플래그 차이"가
  적혀 있었는데 그 노트를 열지 않았다. (실행 가능한 명령을 내놓기 전에 환경 노트를 먼저 본다.)

### 3.3 공개 노트에 문제와 같은 크기를 예시로 썼다 (2회째 사고)
- `Use_After_Free` 에 56/64 바이트 offset, `Stack_Frame_And_Call_Ret` 에 32/40 버퍼 구간 — 실제 문제와
  **같은 숫자**였다. 커밋 전 diff 스캔(문제명·주소·플래그 패턴)은 통과했는데 *크기 일치*는 패턴 스캔이
  못 잡는다. 사람 눈으로 다시 읽어 잡았고 합성값(24/32, 48/56)으로 교체.
- 2026-09-29 의 "공개 예시는 **처음부터** 합성값"을 지키지 못했다. 이번에도 *나중에* 치환했다.
- 개선: 공개 노트에 숫자가 들어가는 순간 "이 숫자가 문제에서 온 것인가?"를 자문한다. 스캔은
  *패턴*만 본다 — 크기·offset 같은 값은 스캔이 못 본다.

### 3.4 응답 하나가 safety classifier 에 중단됐다
- 노트 작성 요청에 대한 응답이 도중에 끊겼고 파일은 쓰이지 않았다. 무엇이 걸렸는지 에이전트는 모른다.
  재시도를 요청받아 같은 범위로 다시 썼고(flag·host 마스킹 유지) 이번에는 통과했다.
  원인 불명이므로 **재발하면 어느 부분이 걸리는지 먼저 좁혀 본다** (기록만).

## 4. Struggle points (JY)

| 지점 | 실제로 일어난 일 |
|---|---|
| **정수 / 텍스트 / 바이트** | **3세션 연속.** 이번엔 `b'0000000000401323'` — 글자 16개를 주소로 썼다. 에러 없이 조용히 틀린다. `p64`/`struct.pack` 로 해결 |
| **payload 를 안 보냄** | **3세션 연속** (`print(payload)` 만 있고 `send` 없음). 다음 문제에서는 JY 가 먼저 쓰는지 본다 |
| `struct` 인자 | "각 인자별 정리해줘"를 두 번 요청. 접두사·타입 코드·`Q` 의 뜻을 따로 물었다. → `Binary_Number_Encoding` §J |
| `repr().encode()` vs raw | `fread` 문제에도 `repr().encode()` 를 쓰려 했다. **입력 함수가 텍스트 파서인지 raw 인지**가 판단 기준 (`scanf("%lf")` vs `fread`) |
| offset 셈 | `[rbp-0x20]` 에서 48 이라 답함 (8 을 두 번 더함). `[시작,끝)` 표로 교정. 전에도 `code[8]` vs `code[9]` 로 같은 종류 |
| 레지스터 개념 | "rdi 가 실행 중에 정해진다고?" — 레지스터가 특별한 게 아니라 **그 인자의 값**이 실행 중에 정해진다는 구분 |
| `rsp` vs `rbp` 칸 | `[rsp+X]` 와 `[rbp-Y]` 가 다른 칸이라고 그림. 같은 칸의 두 이름 |
