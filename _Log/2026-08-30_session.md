## 1. 해결한 것 — GoN Forensic / Header

정상적으로 열리는 PNG 에서 숨겨진 영역을 찾는 문제. **선언값 vs 실측값** 대조로 해결.
상세는 `Wargames/GoN/Forensic_Header.md` (local-only).

증거 사슬(이게 이 세션의 실질 자산):

```
① grep -abo 오프셋 9개  ↔  파서 태그 위치 9개        완전 일치  → 순회 정확성 (독립 2방법)
② p == len(d) 정확히 착지                            → '길이 필드 조작' 가설 사망
③ CRC 12개 중 정확히 1개 불일치                       → 위치를 레코드 단위로 특정
④ 헤더 필드 규격 검사 8/8 통과                         → 규격 위반은 아님 (유효값 바꿔치기)
⑤ 압축 해제 실측 ≠ 헤더에서 계산한 기대값              → 선언값이 거짓
⑥ 실측 ÷ 줄 크기 나머지 0                             → 두 필드 무죄, 한 필드 유죄
⑦ 원래 값 복원 → CRC 가 저절로 일치                    → 그 값이 '원본' 임을 증명
```

**⑦이 결정적이었다.** 크기 검사는 "모순 없음"까지고, CRC 일치는 "바로 그 값"을 증명한다.

## 3. Struggle Points (정직하게)

**a. 명세서를 읽고도 손에 안 남았다.**
IHDR 필드 목록을 이미 붙여넣고 읽었는데, 나중에 그게 필요해지자 "어디서 참조한 거냐"고
되물었다. 그때는 컨테이너 층을 걷는 중이라 무시한 게 맞는 판단이었지만 — **읽은 것을 표로
옮겨두지 않으면 다시 찾아야 하고, 다시 찾을 때마다 놓친다.** Phase 0 에서 표를 먼저 만드는
습관이 여기서 값을 했고, 안 만든 층에서는 대가를 치렀다.

**b. 약한 신호를 쫓았다 — 두 번.**
"IDAT 이 7개나 되니 이상하다"(규격이 `may` 로 허용하는 정상 구조), "pHYs 가 9바이트라
수상하다"(CRC 는 일치했고 규격도 통과). **도구가 낸 객관적 신호 하나가 눈으로 본 인상보다
훨씬 강한 증거**라는 걸 두 번 겪고 나서야 잡혔다. 판단 기준은 항상 "명세서가 `shall` 로
강제한 것을 어겼는가".

**c. 타입/표기 혼동에서 세 번 막혔다.**
- `f"{...b"..."}"` — 컨테이너 Python 3.11 은 f-string 안 따옴표 재사용 불가(PEP 701 은 3.12)
- 10진수 앞에 `0x` 를 붙여 16진수가 된다고 오해 → 40비트짜리 값이 나왔다
- 그걸 고친 뒤에도 **따옴표를 유지**해서 `int == str` 비교 → 조용히 항상 False
  (따옴표 *종류*를 바꾸는 시도를 두 번 했다. 바꿔야 했던 건 존재 여부였다.)

**d. 슬라이스를 두 번 틀렸다.**
CRC 덮는 범위를 처음엔 CRC 필드 자체 위치로, 두 번째는 Chunk Type 4바이트를 빠뜨린
`[p+4 : p+4+n]` 으로. **길이 검산(`b − a` 가 덮어야 할 크기 합과 같은가)** 을 습관화하니
그 자리에서 잡혔다.

**e. 내가 과하게 시킨 것 둘 (교정됨)**
- CRC 재계산 후 덮어쓰기를 시켰는데 — **JY 가 "이미 불일치니 되돌리면 원래 값과 맞아야
  하지 않냐"고 먼저 짚었다.** 맞는 지적이고, 덮어썼다면 판정 능력이 0이 됐을 것이다.
  **이 세션에서 가장 좋은 판단이었다.**
- 수정 후 PIL 재인코딩을 검증 단계로 제시했으나, 파서가 이미 전수 검증한 뒤라 중복이었다.
  남는 이유는 "호스트 이미지 파서에 원본을 안 먹인다"뿐이고 이 경우엔 약했다.

**f. 환경 마찰 — 셋 다 원인까지 규명함**
- `vi` 화살표키가 글자를 삽입 → `vim-tiny` 가 `/etc/vim/vimrc.tiny` 의 `set compatible` 을
  읽어 삽입 모드 화살표 매핑이 꺼짐. `ESC O A` 세 바이트가 세 명령으로 실행된 것.
  → Dockerfile 을 `vim` 으로 교체, 재빌드. `syntax on` 도 함께 켜짐(`defaults.vim` 이 살아남).
- 컨테이너에 한글이 깨짐 → `LANG` 미설정으로 vim 이 `encoding=latin1`. **표시만이 아니라
  편집도 망가진다**(커서/삭제가 바이트 단위). → `/work` 코드는 ASCII 로 통일. Python 은 무관.
- 컨테이너 Python 3.11 vs 호스트 3.13 — 호스트에서 편집하고 컨테이너에서 실행하는
  워크플로에서 **버전 낮은 쪽 문법에 맞춰야** 한다.
