# 2026-09-26 — Harness v4.1

Not a learning session — a `/harness-audit` run with a self-improve loop
(audit → build → adversarial verify → fix, until a verify round came back dry).
Canonical description of the result: `_System/Harness.md`.

## What was done

1. **Audit** (9 read-only lanes): state layers, credential detection, pre-push
   design, write guard, parser false positives, permission semantics, doc
   drift, usage evidence, context budget. Pre-change full backup taken first.
2. **Shared scanner** `scripts/claude/secret_scan.py` (new): one rule set for
   pre-commit, pre-push and the write guard. Catches 10-char (Leviathan-style)
   passwords, judges every whitelist clause on the token, decodes UTF-16/32,
   treats a stray NUL as text, strips zero-width chars and numeric entities.
3. **pre-commit** rewritten around it: one index walk, case-folded no-publish
   paths, `.nopublish` markers of any type, and any `.gitignore`d path in the
   index is a violation. Fails closed if the scanner is missing or crashes.
4. **pre-push** (new): signature `G` by the declared key, no-publish/ignored
   paths in every pushed tree, every new blob and message scanned. pre-commit
   also installed as pre-merge-commit.
5. **session-guard** now verifies what it installs, reports `core.hooksPath` as
   DISARMED, checks the real signing key, restores missing markers (the
   Pwn_College tree had none), names unexpected hooks.
6. **Parser**: comment-line / blank-line / crash-fail-open holes closed, key
   stores added, audit-read false positives removed — then declared TERMINAL.
7. **§1.5** became a mechanism: operator-kept `.git/info/identifiers`.
8. **Docs**: CLAUDE.md v4.1 (harness internals relocated verbatim to
   `_System/Harness.md`, move check lost = 0, CLAUDE.md −15%), drift fixed in
   Vault_Structure / Frontmatter / Lite template / README, drift checks added.

## Struggle points / honest notes

- **A verifier subagent committed into the real repo.** Its probe script used
  `$(cd …)`, stayed in a subshell, and ran git in the real repo: an unsigned
  commit of synthetic-secret files on `main`. The bash guard cannot see inside
  `bash script.sh`. Nothing was pushed; the auto-mode classifier refused the
  agent's own `git reset`, so JY ran the restore. The verifier's suggested
  cleanup would have `rm -rf`'d the real `Wargames/` tree on this
  case-insensitive disk — caught by reading it before relaying. Lesson saved to
  agent memory: tripwire every probe script, snapshot + diff around every lane.
- The old pre-commit let that commit through (UTF-16, NUL, label and `<…>`
  shapes), and a case-variant no-publish path too — real-world proof of the
  audit's findings, not just a lab result.
- My own edits wrote `\u` escapes as literal invisible characters into the
  scanner source; caught by a sweep before applying, rewritten as `chr()`.
- The docs I wrote tripped the new scanner twice (a CamelCase example, a hex
  test literal) — the gate works on its own authors.
- The permission-semantics lane left most questions unverified; only "settings
  `ask` forces a prompt in auto mode" is relied on.
