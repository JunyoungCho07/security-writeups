# Session 2026-09-27 — 첫 pwnable, 그리고 정적 분석의 범위

## 0. 세션 성격

teaching 세션. §1.4 유지 — building block과 *왜*만 제공, offset·주소·payload·walkthrough
미제공. **JY의 첫 pwnable**이고 C·어셈블리 무경험 상태에서 시작했으므로, 강의 비중이
문제 해결 비중을 크게 넘었다.

문제 특정 진행상황은 local-only 트리의 MOC에. 이 로그는 **개념·도구·막힌 지점**만 남긴다.

## 1. 해결

스택 BOF로 제어 흐름을 탈취하는 최소 패턴(ret2win)을 **정적 분석만으로** 구성해 원격 1회
성공. 리버싱 툴(IDA/Ghidra) 없이, 호스트에 아무것도 설치하지 않고 끝냈다.

JY가 스스로 도달한 것:
- 호출되지 않는 함수의 존재가 **의도의 증거**라는 추론
- 버퍼 크기와 읽기 상한의 불일치 = 취약점 지점
- `sizeof`를 쓸 줄 아는 사람이 숫자를 손으로 박은 **내적 모순**이 실수가 아니라 의도라는 판단
- `exit`과 `return`의 차이를 "돌아갈 지점이 필요한가"로 환원
- 리틀엔디안 판정
- 프레임 좌표에서 offset 계산 — **첫 시도에 정확**

## 3. Struggle points (정직하게)

### JY 쪽
1. **스택/힙 성장 방향을 반대로 알고 있었다.** 원인은 오해가 아니라 **그림 관례** — 낮은 주소를
   위에 그리는 자료에서는 "스택은 아래→위"가 맞다. 주소로 실측해 해소. **교훈: 위/아래를
   쓰지 말고 낮은/높은 주소로 말한다.**
2. **"RIP를 오버플로한다"를 두 번 말했다.** RIP는 레지스터라 덮을 수 없고 `ret`이 중개한다.
   이 중간 링크를 접으면 canary/PIE/NX가 왜 다른 우회를 요구하는지 설명이 안 된다. 반복
   교정 대상.
3. **주소 고정 여부를 `force_align_arg_pointer` 때문이라고 추론했다.** 결론은 맞았지만 근거가
   틀렸다 — `e_type`(PIE)이 정한다. 다른 문제에서 같은 추론이 통하지 않는다.
4. **정적 분석과 동적 실행을 하나로 묶어 생각했다** → "내 맥에서는 못 뜯는다"는 잘못된 결론.
   이 혼동이 세션 초반의 환경 논의를 크게 부풀렸다.
5. **payload 생성 스크립트를 이해하지 못했다.** 여기서 나온 질문 — "nc에 `0x96`이라고 적으면
   char 4개로 들어가지 않나" — 이 세션에서 **가장 예리한 질문**이었고, 임의 바이트열을 키보드로
   만들 수 없다는 사실을 스스로 짚은 것이다.

### 내 쪽 (에이전트 오류)
1. 🔴 **검증하지 않은 플래그를 줬다.** `objdump --disassemble=SYM`은 GNU 문법이고 macOS의
   LLVM판에서는 `unknown argument`다. JY가 두 환경에서 실패한 뒤에야 실측해 정정
   (`--disassemble-symbols=`). **CLAUDE.md §7 "터미널 출력 조작 금지"의 사촌 — 미검증 명령 제공.**
2. 🔴 **환경 요구를 과대평가했다.** 1턴에서 전용 x86_64 QEMU VM을 추천했으나, ① 정적 분석은
   호스트에서 되고 ② 실행은 기존 VM의 amd64 컨테이너로 된다. **JY의 반박("정적만으로 안
   끝나나")이 옳았고 내가 추천을 수정했다.**
3. 🔴 **주체를 흐린 문장.** "1턴에서 읽은 바이트"라고 썼는데 읽은 건 나다. 그 결과 JY가 내
   말을 믿고 전제를 받아들였다 — pwn에서 가장 나쁜 습관을 내가 유도했다. JY가 잡아냈다.
4. **틀린 사실 주장.** `Concepts/Binary/`가 "이번이 첫 입주"라고 했으나 이미 5개 노트가 있었다.
   `git status`/`find` 없이 기억으로 말한 결과.
5. **§1.4 봉쇄가 허술했다.** 디스어셈블리 읽는 법을 가르치려고 만든 테스트 바이너리를 대상과
   구조적으로 거의 동일하게 작성해, 화면에 답에 준하는 숫자가 떴다. 경고를 붙여 수습했으나
   애초에 다른 크기로 만들어야 했다.
6. **정찰 순서를 거꾸로 가르쳤다.** `nm | grep -E '아는 이름들'`은 **이미 아는 것만** 보여준다.
   처음 보는 바이너리에는 `nm --defined-only -n` 전체가 맞다. `-i`도 불필요했다.

## 6. JY의 노선 결정 — raw before tools

> "나중에 도입하자 pwntools는 bof234도 쌩으로 해보면서 기초원리에 익숙해지고 툴을 쓰자.
> 아직 모호하고 hands on이 아니라 더 훈련이 필요하다"

근거: 자동화가 가리는 것이 정확히 학습 대상이다 — `p64`=엔디안, `ELF().symbols`=심볼 테이블,
`cyclic`=프레임 구조, `checksec`=ELF의 어느 구조에 무엇이 있는지. 넷 다 이번에 손으로 했다.

**도입 신호는 JY 자신의 지루함** — 같은 코드를 다시 타이핑하는 것이 노동으로 느껴질 때.
그 전에는 권하지 않는다. `one_gadget`/`ropper --auto`/`angr`는 영구 제외 (sqlmap과 동일 범주).

## 7. 다음 타깃

1. **방어 기제를 ELF에서 직접 판독하기** — `checksec` 없이. NX는 program header,
   canary는 심볼 테이블, RELRO는 dynamic section, PIE는 `e_type`. **네 구조가 각각 다르다.**
2. 열린 퀴즈: 네 방어 중 **이번 payload를 무력화하는 것은 몇 개인가.** (NX는 아니다 —
   목적지가 `.text`이므로. 이유를 설명할 수 있어야 한다.)
3. 미완 표: `exit(1)`(=1) / SIGSEGV(=139) / 정상종료를 화면 출력 + `echo $?`로 구분하는 표.
   로컬 실행을 건너뛰어 실측 기회를 잃었다 — 다음 문제에서 채운다.
