# Session 2026-09-08 — 정밀도 type-confusion 해결 + RSA/공급망 학습

## 0. 세션 성격

teaching/help 세션. JY가 직접 푸는 원칙(§1.4) 유지 — building block과 *왜*만 제공,
walkthrough·payload·정답 미제공. local-only 세트의 Web/Crypto/Misc 문제 4개를 넘나들었고,
그중 1개를 해결했다. 문제 특정 진행상황은 local-only 트리의 MOC에.

## 1. 해결 ✅ (Web 카테고리 1문제)

핵심 개념은 **type differential across a trust boundary** — 같은 값을 인가 경로와 실행
경로가 **서로 다른 수 타입으로** 읽으면, 부동소수점의 유효숫자 한계 위에서 두 해석이
어긋난다. 서명(MAC)은 **바이트를 인증하지 의미를 인증하지 않으므로**, 서명 주체가 스스로
틀린 타입으로 판단하면 위조 없이 경계가 뚫린다.

일반 이론은 공개 노트로 원자화했다 → §2. 문제 특정 파라미터·재현 절차는 local-only 트리에
(flag 마스킹).

- 검증 방식: 작은 값으로 붕괴를 먼저 재현 → 대상 언어 컨테이너로 두 파싱 경계를 각각
  재현 → 서명 payload를 디코드해 "서명이 내 바이트를 그대로 운반한다"를 확인.
  **가설을 세 층에서 독립적으로 확인한 것이 이 세션의 방법론적 수확.**

## 2. 개념 원자화 (lite 1개 신규)

| 노트 | 도메인 | 무엇을 팠나 |
|---|---|---|
| `Floating_Point_Precision` | Binary | IEEE-754 double 비트구성, `2^53` 정수 경계, ULP=`2^(k−52)`, 큰-정수 붕괴 + 소수 부정확(0.1+0.2), 그리고 **type/parser differential across a trust boundary** 보안 귀결 |

작은 숫자로 직접 `pow`·`struct` 비트분해를 돌려 확인. 역링크 3개(Binary_Number_Encoding,
Twos_Complement, Checksum_Hash_MAC) 상호 연결.

## 3. 착수했으나 미해결 (정직히)

- **Crypto** — JY가 RSA를 아예 모른다 하여 **밑바닥부터 강의**함: 모듈러 산술 → 오일러
  정리·φ → 트랩도어(`e·d = 1 + kφ`) → 안전성 근거(인수분해 난이도). 공격 유도는 JY 몫으로
  남김. **미해결.**
- **Misc (패키지 공급망)** — 레지스트리 프로토콜을 **공식 스펙까지 내려가** 학습: 인덱스
  루트 규약, 이름-길이 기반 인덱스 경로 규칙, 다운로드 URL 템플릿 치환, 캐럿 버전 해석.
  아티팩트 획득·해제까지 도달 후 중단. **미해결.**
- **Web (다단계 네이티브 파서)** — 게이트웨이 + 워커 + 네이티브 바이너리 구조의 **신뢰사슬
  분석**까지. 무결성 검증이 네이티브 파서에 위임되는 구조가 급소라는 판단. **분석만, 미해결.**

## 4. Struggle points

- 공급망 문제에서 JY가 "감도 안 온다" → 전체를 한 문장으로 압축하는 비유로 재정렬. 그래도 미완.
- **"URL을 어떻게 추측했나"** 에 대해 — **추측이 아니라 스펙**임을 공식 문서로 증명하고,
  레퍼런스 구현의 verbose 출력으로 교차검증하는 법까지 보여줌. **학습 가치 큼** — "왜 여기에
  이 파일이 있는지"는 규약을 읽으면 나온다는 감각.
- RSA를 0에서 세우느라 해당 문제 진도는 못 나감. 정상 — 개념이 먼저다.

## 5. 개념 노트 보류 (정책 충돌 — JY 판단 대기)

표준 정책(EOL §4, `policy-lite-concept-notes`)은 **substantively explored 개념마다 lite 노트**.
오늘 RSA 기초와 패키지 레지스트리 프로토콜은 그 기준을 충분히 넘었다. 그러나 JY 지시가
**"푼 문제만 /eol"** → solved 건의 개념만 원자화하고 나머지는 **보류**함.
