## 1. 해결 — Web / Snowflake Pass ✅

**float64 인가 vs uint64 조회의 type differential.** 인가 단계가 리소스 ID를 `float64`로
비교(`requestedID == float64(item.ID)`)하는데, `~2^60` 근방 double 간격(ULP)이 256이라
차이 1인 restricted↔public ID가 **같은 double로 붕괴**한다. restricted ID를 요청하면 인가는
"public"으로 착각해 payload를 HMAC 서명해주고, 조회 단계는 같은 바이트를 `uint64`로 정확히
파싱해 restricted vault를 꺼낸다. 서명은 위조 불가지만 **서명 주체가 스스로 틀린 타입으로
판단**하므로 위조가 불필요.

- 검증: Python `float()` 비교로 붕괴 확인, golang 컨테이너로 두 경계(`float64` vs `uint64`
  파싱) 재현, token payload base64url 디코드로 "서명이 내 바이트를 그대로 운반" 확인.
- 상세(파라미터·재현): `Wargames/GoN/Snowflake_Pass.md` (local-only, flag 마스킹).

## 2. 개념 원자화 (lite 1개 신규)

| 노트 | 도메인 | 무엇을 팠나 |
|---|---|---|
| `Floating_Point_Precision` | Binary | IEEE-754 double 비트구성, `2^53` 정수 경계, ULP=`2^(k−52)`, 큰-정수 붕괴 + 소수 부정확(0.1+0.2), 그리고 **type/parser differential across a trust boundary** 보안 귀결 |

작은 숫자로 직접 `pow`·`struct` 비트분해를 돌려 확인. 역링크 3개(Binary_Number_Encoding,
Twos_Complement, Checksum_Hash_MAC) 상호 연결.

## 3. 착수했으나 미해결 (정직히)

- **Crypto / RSA 복호 오라클** — raw RSA에 임의 복호 오라클(`ct` 잔여류만 차단, 1회 질의).
  공략축은 곱셈 준동형 **blinding**. JY가 RSA를 아예 모른다 하여 **밑바닥부터 강의**함:
  모듈러 산술 → 오일러 정리·φ → 트랩도어(`e·d=1+kφ`) → 안전성(인수분해) → chall 대응.
  블라인딩 유도는 JY 몫으로 남김. **미해결.**
- **Misc / cargo 공급망** — flag key = `sha256(fingerprint())`, crate는 sparse HTTP
  레지스트리에 있음. Cargo sparse registry 프로토콜을 스펙(공식 문서)까지 내려가 학습:
  `config.json`이 인덱스 루트에 있다는 규약, 이름-길이 인덱스 경로 규칙, `dl` 템플릿
  치환, 캐럿 버전 해석(`"4.2.0"`=`^4.2.0`). crate 다운로드·압축해제까지 도달,
  `fingerprint()` 읽기 직전 중단. **미해결.**
- **Web / 다단계 native-parser 렌더러** — gateway+worker+native 바이너리. 신뢰사슬 분석:
  실행되는 plugin source가 어떤 digest에도 안 묶이고 무결성이 native 파서에 위임됨 →
  그 바이너리 RE가 급소. **분석만, 미해결.**

## 4. Struggle points

- cargo 문제에서 JY가 "감도 안 온다" → 자물쇠상자 비유(그랜마 설명)로 전체를 한 문장으로
  압축("받을 수 있는 라이브러리 함수 하나가 비번을 출력한다") 후 재정렬. 그래도 미완.
- "URL을 어떻게 추측했나 / config.json이 거기 있는 걸 어떻게 아나"에 대해 — **추측이 아니라
  스펙**임을 공식 문서로 증명(레퍼런스 구현 `cargo -v`로 교차검증하는 법도). 학습 가치 큼.
- RSA를 0에서 세우느라 crypto 문제 자체 진도는 못 나감. 정상 — 개념이 먼저다.
